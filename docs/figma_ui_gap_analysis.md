## 1. 审计范围与判定规则

本轮以仓库内更新后的 Figma 原型为基准，覆盖现有 Qt 的全部可见 UI，不再只追踪前序阶段。Figma 的样例账号、样例时间和 `Math.random` 行为仅用于演示，不是产品数据或行为契约，不得复制到 Qt。

结论分为三种证据等级：

- **当前正式证据**：当前 Release 产物的隔离运行记录，可支持对应状态的运行结论。
- **历史旁证**：旧产物的截图或交互记录，只说明当时实现过，不代表当前 Release 通过。
- **静态结论**：来自 Figma 与当前源码的结构对比，必须经运行验收后才能标记通过。

阶段 1 已使用当前 Release 完成代码门禁、隔离 GUI 主题复验和 Qt 浅色/深色差异图；阶段 2 已完成导航、顶栏、搜索、列表和已批准断点的当前 Release 验收。仓库内 Figma 依赖仍缺失，当前 Figma 同尺寸像素对照未执行。几何正确、测试通过和像素一致是不同结论，不互相替代。

## 3. 风险总览

### P0：真实性、安全与破坏性操作门禁

1. **解锁默认值**：固定预填逻辑已移除，并增加 setup、unlock、change 三模式输入默认空的回归测试；仍待当前 Release 和隔离 GUI 验证。
2. **修改主密码真实性门禁**：设置入口和 Application 调用端已禁用真实改密，完整重加密与回滚完成前不再显示成功；真实改密延后至阶段 7。
3. **CSV 导出真实性**：已接通有效条目、AES-GCM 解密、分类解析、原子提交和失败阻断，并增加成功及异常数据测试；仍待构建和运行验收。
4. **明确删除语义**：详情右上角已改为红色删除图标，保留二次确认，并补充删除失败提示；仍待运行态确认危险色、取消和恢复流程。
5. **主密码长度**：setup/change 统一为至少 12 个字符，unlock 不设最小长度以兼容既有短密码；KDF、哈希和同步协议不变。
6. **清除本地数据边界**：已决定清除数据库、主密码记录、Hello 凭据、OAuth Token、缓存、会话和本机设置，云端备份不变；阶段 7 完成确认、失败处理和恢复验证前不展示入口。

### P1：主要结构、状态和反馈差距

- 品牌徽章的 32px/34px 冲突和 QSS 优先级问题已修复；当前 Release 在浅色、深色均呈现 34 × 34px 蓝底。列表服务标识采用稳定的首字母和 `icon_color` 六色色板，不从样例账号推断品牌。
- `PasswordCard` 与 `QListWidget::item` 已统一状态来源；当前 Release 的浅色和深色 default、hover、selected、focus 及键盘焦点均清晰可辨。
- 详情仍有 Figma 不存在的固定副标题，“最近使用”绑定 `updated_at`，操作区与底部按钮位置不同。
- 设置只有顶栏、页签和基础令牌接近；常规、同步、安全三页的信息架构整体不一致，不能以微调间距代替结构性重做。
- Toast 四等级 object name 已有对应 QSS selector；success 的单次、连续触发和超时已通过当前 Release GUI，info/warning/error 仍缺安全运行入口。
- `MainWindow`、`DetailPanel`、`EditorPanel`、`PreferencesPage` 已建立显式主题资源刷新链；当前 Release 验证切换无需重启且关键图标、草稿、页面和选中状态保留。

### P2：密度、布局策略与视觉细节

- Figma 在 1200px 示例视口有 16px 外部留白；Qt 工作区贴满客户区。
- Qt 已采用 `>=1280px` 三列、`1024–1279px` 侧栏加列表/详情切换、`<1024px` 折叠导航加列表/详情切换的响应式策略；桌面详情固定 400px，列表最小 380px，搜索框最大 390px。
- 当前 Release 已测量 1280 × 800、1200 × 800 和 900 × 800；这些几何结果不等于 Figma 像素一致。
- 宽屏列表横向留白和卡片高度已分别统一为 28px 和 60px。
- 侧栏品牌区/新建按钮后的纵向节奏，Qt 约为 16/33px，Figma 约为 32/20px。

## 4. 逐区域差距

### 4.1 全局外壳、导航与列表

Qt 已有 224px 侧栏、68px 共用顶栏、最大 390 × 36px 搜索框、60px 密码卡片及三档响应式结构。当前正式证据还验证了 34 × 34px 蓝色品牌徽章、浅色/深色列表状态、搜索完整流程、长列表滚动和长文本省略，但不证明 Figma 像素一致。

阶段 2 已完成：

- 按 `>=1280px`、`1024–1279px`、`<1024px` 实现布局切换，并完成 1280、1200 和 900 客户区几何验收；
- 对齐侧栏节奏、独立计数徽章、28px 列表留白和 60px 卡片密度；
- 使用首字母和 `icon_color` 色板提供稳定服务标识，不从样例账号推断品牌；
- 覆盖搜索聚焦、输入、清空、备注命中、零结果和键盘导航；
- 覆盖长列表物理滚动、长标题/账号省略及浅色/深色 default、hover、selected、focus。

仍保留的边界是当前 Figma 同尺寸像素对照未执行，侧栏纵向节奏等静态差异不宣称像素一致。

### 4.2 条目详情

新版 Figma 不显示副标题；Qt 固定显示“安全条目 · 已加密保存”。编辑和明确的红色删除操作已放在右上角，但运行态危险色、确认/取消和失败状态尚未验收。时间卡后方的 stretch 仍会把底部按钮推到面板底部。

实现与验收必须同时确认：

- 删除入口明确表达危险动作，必须覆盖确认、取消和失败，不得仅断言点击成功；
- “最近使用”应绑定真实业务字段；若产品没有该字段，应调整标签，不得用更新时间伪装；
- 空详情、正常详情、解密错误和删除后的选中恢复均有明确状态；
- 复制可用 Toast 或行内勾，但账号、密码、网址的反馈必须一致且不会泄露内容；
- 长标题、长字段、链接、滚动、编辑返回与详情刷新无裁切或陈旧数据。

### 4.3 编辑与生成器

[`EditorPanel`](../src/ui/editor_panel.cc) 已实现 400px 抽屉、68px 顶栏、340px 内容区和同一 `QStackedWidget` 内的生成器。当前 Release 已复验抽屉宽度、草稿、密码显示状态和生成器页面跨主题保留；完整编辑/生成流程及当前 Figma 同尺寸参考图仍未覆盖。

后续需覆盖新建、编辑、保存错误、取消、关闭、键盘、滚动、生成、回填和真实持久化。Qt 在所有字符类别关闭时显示错误比原型回退到随机小写更真实，应保留。遗留独立生成器对话框不得与内嵌生成器混为一谈，需明确入口、用途与去留。

### 4.4 设置外壳与常规页

设置页已接近 68px 顶栏、32px 返回按钮、页签和基础控件令牌。差距主要在正文：Figma 有页内标题、说明、最小化到托盘和定制自动锁定；Qt 是主题、空闲自动锁定、剪贴板清理三行。

Qt 的主题和剪贴板能力应保留并重分组。最小化到托盘只能在真实行为、启动恢复和持久化都定义后加入。卡片约 692 × 668px，而 Figma 约 840px 宽并按内容收缩；该尺寸差距低于信息架构优先级。

### 4.5 同步页与 OAuth

Figma 使用页标题、Google 子标题、授权/账号卡、上次同步卡、立即同步和端到端加密提示。Qt 当前为 Drive、立即同步、CSV 导入、CSV 导出四个扁平设置行。CSV 应从同步状态流中分离，但不删除功能。

[`OAuthWizardDialog`](../src/ui/oauth_wizard_dialog.cc) 最小宽 480px，包含开始授权、等待、成功自动关闭和失败重试；它没有完整 Figma 基准和当前运行证据。同步验收必须覆盖未连接、授权取消/失败/成功、已连接、同步中、成功、冲突和错误，并核对按钮禁用、状态刷新和 Toast 语义。

### 4.6 安全页与主密码三模式

Figma 安全页包含页标题、主密码、Windows Hello、离开时锁定和独立危险区；Qt 只有主密码和禁用 Hello 两行。危险区受第 3 节 P0 门禁约束。

[`MasterPasswordDialog`](../src/ui/master_password_dialog.cc) 共用首次设置、解锁和修改三种模式，现为通用 `QFormLayout` 与 `QDialogButtonBox`。Figma 只覆盖修改模式，采用图标标题栏、关闭按钮、纵向字段和分层 footer。视觉重做不能破坏另外两种模式；首次设置、解锁和 Hello 应建立 Qt 自有状态基准。

修改模式必须先解决真实重加密与 8/12 字符契约，再验收旧密码错误、新密码不一致、显示密码、取消、成功和重启后解锁。日志、截图与自动化输入不得包含真实密码。

### 4.7 Qt 独有 UI 与全局状态

- CSV：系统文件选择器与 `760 × 520px` 的预览框，覆盖新增、更新、无效三个 tab；除确认禁用外还要验证空数据、零变更、部分无效和导入失败反馈。
- Toast：覆盖 info、success、warning、error 的文字、颜色、位置、超时、连续触发和主题切换。
- `QMessageBox`：覆盖启动失败、主密码错误、删除确认等系统/通用弹窗，统一按钮顺序、键盘默认项和危险色。
- 空/错误态：覆盖空列表、搜索无结果、空详情、解密错误及同步全状态。
- 主题：覆盖浅色、深色、跟随系统的文字、图标、边框、hover、selected、disabled、focus 和 error。

## 7. 正式验收约束

- 使用 Release 构建，依次运行定向测试、相邻集成测试和全部适用测试；失败、未执行和环境阻塞分开统计。
- GUI 使用唯一隔离目录，不复制现有 `data`，只使用一次性主密码和固定演示数据，不访问真实保险库、云端或认证账户。
- 自动化优先使用 UI Automation pattern；每个动作后断言可观察结果。任一断言失败立即收尾，不自动重跑整段。
- 默认浅色、96 DPI、1200 × 800 客户区；响应式决策后另补 `>=1280px` 及其他选定断点，不能混用验收口径。
- 截图前等待动画稳定，测量实际 geometry/BoundingRectangle，并覆盖 default、hover、focus、selected、disabled、error。
- 参考图优先由仓库 Figma/React 源码按同尺寸渲染；无法渲染时标记“像素对照未执行”，不得用源码阅读替代。
- 证据保存到 `build/acceptance/<stage>/<timestamp>/`，包含日志、环境、Git 状态、交互报告、测量、截图、差异图和结论。
- 只有 Release 构建、定向/集成/回归测试、Windows 自动交互和当前阶段 UI 检查全部通过，才能标记阶段通过。

## 8. 当前结论

当前 Qt 已具备接近 Figma 的宽屏外壳，编辑/生成器结构也已在代码中完成；但设置三页、同步、安全流程和 Qt 独有状态仍缺完整设计与运行证据。阶段 0 的非 CSV 门禁已完成构建、定向测试、全量回归和隔离 GUI 验收；CSV 异常提交路径仍是用户批准的例外，不宣称 CSV 全路径通过。

阶段 1 已在用户批准 info/warning/error Toast 与 Figma 像素对照例外后通过；品牌徽章、三主题运行切换、关键状态保留以及 success Toast 有当前 Release 正式证据。例外项仍保持“未执行”，不能宣称对应 Toast 运行态或任何区域“与新版 Figma 像素一致”。

阶段 2 已通过当前 Release 的代码门禁、受影响增量测试和隔离 GUI 验收：分类与计数、搜索完整流程、长列表滚动、长文本省略、浅色/深色列表状态以及 1280、1200、900 客户区均有可复核证据。Figma 同尺寸像素对照仍未执行，CSV 继续沿用批准例外；后续可按依赖进入阶段 3 的详情与破坏性操作验收。
