# PassVault 本地 Figma 源码与 Qt UI 差距分析

> 审计日期：2026-07-25  
> 进度更新：2026-07-30
> 设计基准：[`figma/src/app/App.tsx`](../figma/src/app/App.tsx) 及 [`figma/src/styles/`](../figma/src/styles/)  
> Qt 实现：[`src/ui/`](../src/ui/) 与 [`resources/qss/`](../resources/qss/)  
> 用途：作为后续分阶段修复和人工截图验收的唯一差距清单

## 1. 基准与判定原则

从本次审计开始，不再把无法通过 MCP 读取节点的 Figma Make 链接或历史截图作为结构尺寸的主依据。仓库内 `figma/` 是目标 UI 的可执行 React/Tailwind 源码，包含保险库、详情、编辑抽屉、抽屉内密码生成器、三类设置页和修改主密码弹窗，因此本报告直接以该源码为基准逐项对比当前 Qt 代码。

对比时采用以下规则：

- **视觉 / 结构差距**：目标源码与 Qt 在布局、尺寸、颜色、字体、层级或可见状态上不同，需要进入修复计划。
- **产品能力扩展**：Qt 比目标原型多出的真实功能，例如深色主题和 CSV，不应为追求一致而删除；只需调整放置位置或视觉层级。
- **原型占位行为**：目标源码中没有 `onClick` 或没有持久化的控件，不要求 Qt 退化为同样不可用。此类项目只比较视觉，不把“Qt 有真实逻辑”判为缺陷。
- **动态数据差异**：条目数量、分类名称和时间文本来自真实数据库，不要求与目标样例数据完全一致。

### 1.1 对比页面

本地目标源码包含 8 个可独立验收的页面 / 状态：

1. 保险库主界面（外壳、侧栏、共享顶栏、密码列表）
2. 条目详情
3. 新建 / 编辑密码抽屉
4. 抽屉内密码生成器
5. 常规设置
6. 同步设置
7. 安全设置
8. 修改主密码弹窗

主密码设置 / 解锁、独立 OAuth 向导、CSV 导入预览和 Toast 在本地 Figma 源码中没有完整对应设计，不能进行逐像素比较，详见第 10 节。

## 2. 结论摘要

当前 Qt 已经完成目标的基础配色、圆角外壳、224px 侧栏、共享 68px 顶栏、列表与详情双列结构和详情信息卡。此前文档所述“顶栏只属于列表”“列表与详情顶部错层”“顶栏没有底部分隔线”均已不符合当前代码：这些结构已经在 [`src/ui/main_window.cc`](../src/ui/main_window.cc#L107) 中修正并通过阶段 1 验收。

目前最显著的剩余差距是：

1. **设置页内容层级和项目不一致**：同步账号卡、认证状态、安全操作和常规设置项目仍未按最新目标收敛。
2. **主界面仍有可见细节差异**：列表卡片左右边距为 20px 而非 28px，卡片高度更高；侧栏计数样式和详情头部也未按目标源码实现。
3. **目标字体未随应用分发**：目标明确使用 Noto Sans SC 和 DM Mono；Qt 普通文本依赖系统字体，等宽字体也只提供回退链。
4. **关键状态缺失或语义不符**：品牌头像、行内复制成功反馈、真正的“最近使用”数据尚未实现；详情仍用普通“更多”图标直接触发删除。
5. **阶段 2 已按最新原型重做**：编辑抽屉改为 400px 单列表单，并把密码生成器放入同一抽屉页面栈；代码与自动化断言已更新，仍待构建和人工截图验收。

### 2.1 页面差距总览

| 页面 / 状态 | 当前结构接近度 | 最大差距 | 优先级 |
|---|---|---|---|

| 新建 / 编辑密码 | 高 | 代码已按 400px 单列抽屉更新，待构建与截图验收 | 验收中 |
| 抽屉内密码生成器 | 高 | 已复用真实生成算法实现目标页面栈，待截图微调 | 验收中 |
| 常规设置 | 中 | 缺少页标题与“最小化至托盘”，多出主题/剪贴板项目 | P1 |
| 同步设置 | 中低 | 缺少连接徽章、同步摘要和目标按钮组 | P1 |

### 3.2 字体仍未对齐（P0）

目标在 [`figma/src/styles/fonts.css`](../figma/src/styles/fonts.css) 中加载：

- Noto Sans SC：400 / 500 / 600 / 700，用于全部常规界面文本；
- DM Mono：400 / 500，用于快捷键和密码；
- Playfair Display：已导入，但当前 `App.tsx` 没有实际使用，不需要移植。

Qt 没有发现 `QFontDatabase::addApplicationFont()` 或应用级 Noto Sans SC 设置。普通中文文本使用 Windows / Qt 默认字体；密码和快捷键虽写有 DM Mono，但没有打包字体，实际会落到 Cascadia Mono、Consolas 等回退字体。

影响：中文字符宽度、粗细、基线和换行均会变化。应先统一字体，再进行最后一轮 1～2px 间距验收。

### 3.3 阴影和层级仍未对齐（P1）

目标包含三类明显阴影：

- 外壳：`0 24px 70px rgba(52,72,99,.12)`；
- 选中条目：`0 3px 10px rgba(53,105,193,.09)`；
- 编辑抽屉：`-18px 0 45px rgba(50,73,105,.14)`。

Qt 令牌中虽然存在阴影概念，但 QSS 不支持 CSS `box-shadow`，当前也没有对应 `QGraphicsDropShadowEffect` 或自绘阴影。结果是外壳、选中卡片和抽屉的层级比目标更平。

### 3.4 响应式策略不同（P2 / 产品决策）

目标在窄宽度下会隐藏侧栏，并在小于 `xl` 时把列表和详情改为上下排列；搜索框也可以从 390px 向下收缩。Qt 固定为桌面三栏，侧栏 224px、详情 400px、搜索框 390px，列表最小宽度 380px。

如果产品只支持桌面宽窗口，可保留 Qt 方案，但应设置与该布局匹配的最小窗口宽度；否则需要增加窄窗口降级布局。

### 3.5 Qt 的合理扩展

Qt 支持跟随系统、浅色和深色三种主题，而目标只定义浅色。该能力不应删除，但深色主题没有 Figma 基准，需要单独验收。

### 6.3 抽屉内密码生成器

- 当前密码预览和行内重新生成按钮；

Qt 在全部字符类别关闭时保留真实错误提示，不退化为原型的隐式小写字母回退。该差异属于安全的产品行为扩展。阶段 2 仍需在 1200 × 800、100% DPI 下构建并截图确认字体基线、滚动区域和底栏实际高度。

- 桌面内容区 padding 40px，卡片最大宽度 920px；

### 7.2 当前 Qt

- 顶栏高度和卡片最大宽度已对齐；
- 顶栏标题在 QSS 中为 22px，返回按钮为 36px；

- 自动锁定使用 1～120 分钟 SpinBox。

### 7.3 差距与处理原则

| 差距 | 处理原则 | 优先级 |
|---|---|---|
| 顶栏标题 22px 而非 16px，返回按钮 36px 而非 32px | 按目标收敛 | P1 |
| 桌面外边距 24px 而非 40px | 按目标收敛，同时保留窄窗口降级 | P1 |
| 页签内容顶部 20px 而非 28px | 按目标收敛 | P2 |
| 缺少“常规设置”标题和说明 | 补齐 | P1 |
| 设置行上下 padding 为 12px，而非 16px | 调整行高和节奏 | P2 |
| 缺少“最小化至托盘” | 仅在实现托盘行为后显示；不要做无功能开关 | P1 / 产品能力 |
| 自动锁定使用 SpinBox 而非下拉框 | 可保留更灵活的输入，但视觉尺寸应接近目标 | P2 / 产品决策 |
| 多出主题和剪贴板设置 | 属于真实能力，不删除；可放在目标两项之后或新增“外观/隐私”分组 | 产品扩展 |

### 8.3 差距与处理原则

## 9. Page 6 — 安全设置

### 9.1 目标

- 页内标题“安全设置”和说明“保护你的保险库与本地数据”；
- 内容内还有“安全 / 保护你的加密保险库”的分区标题；
- 主密码行，按钮文案“修改主密码”；
- Windows Hello 开关；
- “离开时锁定”开关；
- 红色文本操作“清除本设备的本地数据”。

目标开关尺寸为 36 × 20px，白色圆点为 16px。

### 9.2 当前 Qt

- 只有主密码和 Windows Hello 两行；
- 缺少页面标题、分区标题、离开时锁定和清除本地数据；
- 主密码按钮文案为“修改...”且说明文本更长；
- Hello 使用 `QCheckBox`，代码设置属性 `class="toggle-switch"`，但 QSS 实际选择器是 `QCheckBox[variant="switch"]`。

### 9.3 差距

| 差距 | 影响 | 优先级 |
|---|---|---|
| Hello 属性与 QSS 选择器不匹配 | 很可能退化为普通 16px checkbox，属于明显视觉错误 | P0 |
| QSS 预备开关为 40 × 22px，而目标为 36 × 20px，且没有滑块圆点绘制 | 即使修正属性也不能一比一还原 | P1 |
| 缺少页内标题、说明和安全分区标题 | 信息层级不足 | P1 |
| 缺少“离开时锁定” | 目标安全能力缺失 | P1 |
| 缺少“清除本设备的本地数据” | 目标危险操作缺失 | P1（必须先设计确认与数据擦除语义） |
| 主密码按钮文案和说明不同 | 视觉与文案不一致 | P2 |

“清除本地数据”是不可逆操作。实现时必须增加明确的二次确认、说明云端数据是否保留，并验证当前会话密钥、数据库文件和本地令牌的清理范围，不能只添加一个外观按钮。

## 13. 最终判断

当前 Qt 的主界面宏观结构已经接近本地 Figma 源码。阶段 1 的共享顶栏、双列顶部基线和横向分隔线已经完成并通过此前验证；外壳留白和顶栏控件垂直错位也已完成代码修正并增加回归断言。阶段 2 已按 2026-07-30 最新原型重做为 400px 单列抽屉，并加入同抽屉密码生成器页面；通过定向测试和人工截图验收后，再进入字体与开关、主界面内容细节和设置页修复。

Qt 已有的主题、剪贴板清理、CSV、密码生成、真实同步和数据持久化能力应保留。目标是让这些真实能力服从本地 Figma 源码的布局与视觉语言，而不是把生产实现退化成只具备样例交互的 React 原型。
